# ADR 0006: 지역 연결(이웃 도시와 주고받기)

- 상태: 확정 (2026-11-27, 기획. 구현은 3단계 이후, 지금은 코어 설계에만 반영)
- 상세 설계: [design/region-link.md](../design/region-link.md)
- 근거: [design/research-log.md](../design/research-log.md#region-link)

## 결정

1. 여러 플레이어의 동네를 잇는 기능을 **"지역 연결"**로 부르고, 로드맵 **3단계 이후**에 넣습니다.
2. 방식은 실시간 MMO가 아니라 **비동기 연결**입니다. 각 동네 시뮬은 플레이어 컴퓨터에서 돌고, 서버는 동네 사이의 **경계 데이터(요약값)만 보관·중계**합니다. 서버 없이도 혼자 하는 게임은 언제나 완전히 돌아갑니다.
3. 교환 주기는 플레이어 결정 주기와 같은 **계절(게임 내 90일)**입니다. 이웃이 보낸 값은 다음 계절에 반영됩니다(한 계절 지연).
4. 이웃은 **실제 지리**로 정합니다. 동네 경계를 넘는 도로·철도·하천·전력선이 있으면 이웃입니다.
5. 오프라인이거나 아무도 맡지 않은 이웃은 **가상 이웃**(공공 통계 기반 규칙 모델)이 대신 값을 냅니다.
6. 조작 방지는 **결정론적 재시뮬 검증**으로 합니다. 같은 맵·시드·명령 기록·받은 경계 입력이면 같은 경계 출력이 나와야 하고, 서버(또는 다른 플레이어)가 표본을 다시 돌려 확인합니다.
7. **지금 할 일은 두 가지뿐입니다.**
   - 코어에 **경계 포트**를 둡니다. 혼자 할 때도 가상 이웃이 포트를 채웁니다.
   - 코어를 **플랫폼 간 결정론**으로 만듭니다(정수·고정소수점 상태, 고정 순서, 상태 해시).

## 이유

- **SimCity(2013)의 교훈.** 지역 플레이는 통근자·쇼핑객 같은 지역 공용 데이터를 서버에 두는 방식이었고, 실제 도시 시뮬은 로컬에서 돌 수 있었습니다(오프라인에서도 약 20분 타이머 전까지 계속 시뮬됨). 그런데 항상 온라인을 강제해 출시 후 약 일주일 동안 사실상 플레이가 불가능했습니다. 연결은 덧붙이는 재미여야 하고 실행 조건이 되면 안 됩니다.
- **실시간 락스텝은 맞지 않습니다.** 결정론 락스텝은 입력만 보내 대역폭이 작지만, 모든 참가자가 같은 틱을 함께 돌려야 해서 가장 느린 참가자를 기다립니다(Factorio, Gaffer). 서로 다른 시간대의 전 세계 플레이어가 각자 빨리 감기로 계절을 돌리는 이 게임에는 비동기 교환이 맞습니다.
- **계절 주기**는 이미 정한 게임 루프(관찰 → 결정 → 계절 진행 → 브리핑, [game-loop.md](../design/game-loop.md))와 같아서 새 시간 단위를 만들지 않습니다. 교환량도 계절마다 경계 포트 수십 개의 요약값이라 아주 작습니다.
- **결정론은 지금 넣어야 싸게 듭니다.** 부동소수점 결과는 컴파일러·CPU·빌드 설정에 따라 달라질 수 있고, IEEE 754도 모든 시스템에서 같은 결과를 보장하지 않습니다(Gaffer가 인용한 Markstein). 나중에 코어 전체를 고치기보다 처음부터 정수·고정소수점으로 쓰는 편이 쌉니다. 결정론은 지역 연결이 아니어도 리플레이, 버그 재현, 시나리오 테스트(이슈 #5, #12)에 바로 쓰입니다.
- **경계 포트는 혼자 하는 게임에도 필요합니다.** 평택역 원도심 1.5km 구역(ADR 0005)만 시뮬해도 바깥에서 들어오는 통근 차량, 상류에서 내려오는 통복천 물이 있어야 현실적입니다. 지금 "바깥 세계"를 포트로 만들어 두면 나중에 그 자리를 실제 플레이어로 바꾸기만 하면 됩니다.

## 검토한 대안

- **실시간 공유 월드(MMO 서버가 모든 도시를 돌림):** 서버 비용이 플레이어 수에 비례하고, 서버가 멈추면 게임도 멈춥니다. 오픈소스 프로젝트가 감당하기 어렵습니다.
- **결정론 락스텝 멀티플레이(한 지역을 여럿이 동시에):** 친구끼리 한 동네를 같이 운영하는 협동 모드로는 나중에 검토할 만하지만, 전 세계 비동기 연결의 기본 방식으로는 대기 문제가 큽니다.
- **상태 전체 동기화:** 수만 명 시민 상태를 보내야 해서 대역폭이 크고, 필요도 없습니다. 이웃은 내 도시 내부가 아니라 경계를 넘는 흐름만 알면 됩니다.
- **검증 없이 신뢰:** 순위표와 이웃 영향이 조작값에 오염됩니다. 순위표가 없는 사적 연결(친구끼리)만 허용하는 선택지로 남겨 둡니다.

## 결과

- 코어 API에 경계 입출력과 상태 해시가 생깁니다([architecture.md](../architecture.md)). 명세는 [region-link.md](../design/region-link.md)에 있습니다.
- 맵 패키지에 **경계 관문(gate)** 목록이 필요합니다. 구역 테두리를 넘는 도로·하천 지점입니다. 1단계 GIS 작업 뒤에 스키마에 추가합니다.
- 코어 담당은 이슈 #4(도로 그래프)·#5(차량 이동)에서 다음을 지킵니다. 경계 관문 노드를 일반 노드와 구분하고, 결정론 테스트에 상태 해시 비교를 씁니다.
- 실제 지명이 들어가므로 동네 이름·뉴스 문구의 공개 범위와 신고 기능(정치 조롱, 혐오 표현)을 3단계 설계 때 정합니다.
- 서버에는 개인 정보가 아닌 동네 단위 집계값만 둡니다.
