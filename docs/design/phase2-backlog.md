# 2단계 작업 목록: 인구·경제·기후·AI 보좌관

- 상태: 계획 (2026-11-28). GitHub 이슈로 옮겨 순서대로 진행합니다.
- 2단계 목표: 평택역 원도심에서 **한 계절을 진행하면** 인구·재정·통근·폭염·침수 지표가 나오고, 정책(녹지·투수면·도로·세율)을 바꾸면 그 지표가 달라지며, AI 보좌관이 "무엇이 왜 바뀌었는지"를 근거와 함께 설명한다.
- 전제: [ADR 0007](../adr/0007-time-model.md)(틱 100 ms, 계절 = 대표일 방식), [ADR 0003](../adr/0003-climate-system.md)(폭염·침수, 30 m 격자), [balance.md](balance.md)(1단계 가정과 권고), [climate.md](climate.md), [policies.md](policies.md).
- 규칙: 새 데이터 소스는 쓰기 전에 **출처·라이선스를 직접 확인**하고 [data-sources.md](../legal/data-sources.md)·[research-log.md](research-log.md)에 남깁니다(확인 못 하면 쓰지 않거나 "가정"으로 둠). 근거 없는 계수는 "가정"으로 표시합니다.

## 이슈별 내용

### 1. 계절 진행 API (코어)
- 내용: `Simulation::run_day()`(자정→자정, 대표 평일), `run_season()`(대표일 1개 + 기후 사건일, 결과를 90일로 집계), 하루·계절 경계 이벤트(인구·경제·기후 모델이 붙는 곳). 계절 결과 요약 `SeasonReport`(평균 통근, 통행 수 등).
- 근거: ADR 0007 결정 3·4.
- 완료 조건: 평택역 맵 시나리오에서 `run_season` 두 번 결과 동일, 하루 경계 이벤트 순서 테스트, Python·Godot 바인딩에 노출.

### 2. 결정론 검사 (코어·CI)
- 내용: `state_hash()`(차량·도로·구역·명령 결과 상태의 해시), CI에서 Linux·Windows 결과 해시 비교. 1단계 코어의 f64 계산(이동 시간 ceil 등)이 플랫폼마다 같은지 확인하고, 다르면 정수 연산으로 바꿈.
- 근거: [architecture.md](../architecture.md) 원칙 2(결정론), PR #18(지역 연결) 초안의 결정론 규칙 제안.
- 완료 조건: 같은 시나리오의 `state_hash`가 두 OS CI에서 같음.

### 3. 교차로 신호·차로별 처리량 (코어, #13 권고)
- 내용: 지금은 신호 없이 교차로당 2초에 1대(차로 수와 무관). 방향별 차로당 처리량 + 고정 주기 신호(주도로·부도로 녹색 비율)로 바꿈. 회전 충돌은 단순 규칙.
- 근거: [balance.md](balance.md) 결론 3 — 기본 수요에서 혼잡 배율 0.99. 포화 교통류율·신호 주기 값은 국내 도로용량편람 등에서 **찾아 확인 후** 사용(확인 전에는 가정 표시).
- 완료 조건: 기본 수요(셀당 10명)에서 피크 혼잡 배율 > 1.1이 생기고, 1단계 시나리오 테스트(#12)와 결정론 테스트가 그대로 통과, `balance_sweep.py` 결과를 balance.md에 갱신.

### 4. 인구·건물·지가 데이터 출처 확인 (데이터, ADR)
- 내용: 아래 후보의 제공 단위·이용 조건을 직접 확인하고 ADR로 채택 여부 결정.
  - 통계지리정보서비스(SGIS) Open API — 인구·가구·주택 센서스 통계. API 존재 확인([개발자 페이지](https://sgis.mods.go.kr/developer/html/main.html)), 이용약관 본문·공간 단위(집계구/격자)는 **미확인**.
  - KOSIS 행정구역(읍면동)별 주민등록인구 — 표 페이지가 로그인으로 넘어가고 저작권 정책 페이지 주소가 바뀌어 **미확인**.
  - 국토교통부 건축물대장(층수·세대수·용도), 개별공시지가 — 공공데이터포털 페이지 주소 **미확인**(이전 주소 404).
- 근거: [data-sources.md](../legal/data-sources.md) "새 데이터 소스를 추가하려면 ADR을 먼저".
- 완료 조건: 채택한 소스마다 URL·제공 단위·라이선스·출처 표기 문구가 ADR과 data-sources.md·ATTRIBUTION.md에 있음. 쓸 수 없으면 대체안(가정값)을 명시.

### 5. 인구 모델: 가구·연령 (코어)
- 내용: 주거 셀·건물 → 세대 수 추정(건물 바닥 면적 × 층수(없으면 #9 표시 높이 가정) ÷ 세대당 면적), 동 단위 인구 합계로 보정. 가구원 수·연령대 분포(고령자 비율 — 폭염 가중치에 씀), 통근자 수를 인구에서 계산(지금 셀당 10명 가정을 대체).
- 근거: #4에서 확인한 인구 자료. 건물 층수 태그가 거의 없음([building-height](research-log.md#building-height)) → 건축물대장 확인 전까지는 가정.
- 완료 조건: 평택역 맵의 추정 인구가 #4 자료의 해당 동 인구와 비교 가능(오차를 문서에 기록), 통근 수요가 인구 모델에서 나옴, 결정론 테스트.

### 6. 경제 모델: 토지가치·세금·예산 (코어)
- 내용: 셀 토지가치(기준값 + 접근성·녹지·침수 위험 보정), 재산세·지방세 세수, 계절 예산(세수 − 유지비 − 정책 비용), 누적 부채. 정책 카드 비용 차감.
- 근거: #4의 공시지가(확인되면), 지방재정 구조는 공개 자료로 조사. 확인 전 계수는 가정.
- 완료 조건: 계절 경계에서 재정 지표가 갱신되고 정책 비용이 반영됨, 도로 추가·구역 변경이 토지가치에 방향성 있게 영향(테스트), 5대 지표의 "재정" 채움.

### 7. 기후 입력 자료 (데이터)
- 내용: 기상청 종관기상관측(ASOS) 시간 자료로 2024-07-18 평택 인근 강우를 검증 사례로 준비, 기후 시나리오 파일 형식(연·계절별 일 최고기온 분포, 1시간 최대 강수량 분포) 정의, `synthetic` 시나리오.
- 근거: 기상청 기상자료개방포털 — [ASOS 자료](https://data.kma.go.kr/data/grnd/selectAsosRltmList.do?pgmNo=36)(분·시간·일 자료, 105개 지점), [저작권 정책](https://data.kma.go.kr/cmmn/static/staticPage.do?page=pageCr)(기상청 저작물 자유 이용, **출처 표시 필수**, 공공누리 2~4유형 자료는 별도 확인) — 2026-11-28 확인. 평택에 가장 가까운 지점·AWS 이용 조건은 이 이슈에서 확인.
- 완료 조건: 시나리오 파일 형식이 `schema/`에 있고, 검증용 강우 시계열이 출처 표기와 함께 저장(원본은 data-raw), sample-area.md의 강우 확인 과제 체크.

### 8. 폭염 격자 모델 (코어)
- 내용: [climate.md](climate.md) 폭염 모델 — 셀 기온 = 시나리오 일 최고기온 + 열섬 가산(불투수) − 냉각(수관·공원·수변) → 이웃 셀 확산. 고령자·실외 노동 가중 위험 노출 인구.
- 근거: climate.md 냉각 기본값(Kumar et al. 2024, Li et al. 2024 — [heat-trees](research-log.md#heat-trees)), 토지 피복 레이어(#3). 열섬 가산 계수는 조사 과제.
- 완료 조건: 녹지 비율 높은 셀이 불투수 셀보다 낮게 나옴, 가로수 정책(#10) 적용 시 해당 셀 기온 하락, "기후 안전" 지표(폭염 노출 인구) 계산.

### 9. 내수 침수 격자 모델 (코어)
- 내용: [climate.md](climate.md) 침수 모델 — 셀 유출 Q = C·i·A(유출계수는 토지 피복에서), 도로 셀 하수 용량 차감, D8 흐름으로 저지대에 물이 모임, 수심 임계 초과 시 해당 도로 차선 통행 불가 이벤트(ADR 0004 결과와 연결).
- 근거: 유출계수(Iowa DOT 4A-5 — [runoff](research-log.md#runoff), 한국 기준 교체는 조사 과제), 지형(#2: 통복천 셀이 평균보다 6.2 m 낮음).
- 완료 조건: 검증 강우(#7)를 넣으면 통복천 저지대 셀에 물이 모이고, 침수된 도로를 차량이 우회(교통 연동 테스트), 투수성 포장·저류조(#10)가 최대 수심을 줄임.

### 10. 기후 정책 명령 (코어·schema)
- 내용: 명령 확장 — 가로수(도로 셀 수관 +), 포켓 공원(셀 녹지 +, 구역 변경), 투수성 포장(셀 불투수 −). 비용·부작용(공사 중 차선 축소 등)은 정책 카드 형식([policies.md](policies.md))으로, `evidence` 링크 필수.
- 근거: policies.md 정책 카드 공통 형식, climate.md 냉각 기본값.
- 완료 조건: 명령 예시 JSON과 테스트, 폭염·침수 모델에 효과 반영, 잘못된 대상은 거부.

### 11. AI 보좌관 브리핑 (AI)
- 내용: 계절 전후 스냅샷 비교 → "무엇이 바뀌었고 왜"를 지도 위 근거(셀·도로·구역 ID)와 함께 설명하는 브리핑 JSON. LLM은 틱 밖에서만 부르고(architecture.md 원칙 3), LLM이 없을 때는 규칙 기반 템플릿으로 같은 형식을 만든다. 발언에는 시뮬 통계에 있는 사실만 쓴다([climate.md](climate.md) AI 역할).
- 근거: game-loop.md 브리핑 단계(Neset et al. 2020 — 학습은 디브리핑에서), `ai/src/dongne_ai/llm.py` 어댑터.
- 완료 조건: 같은 스냅샷 쌍에 템플릿 브리핑이 결정적으로 나오고, 브리핑의 모든 수치가 스냅샷에서 검증됨(환각 검사 테스트), LLM 사용은 환경변수 키가 있을 때만.

### 12. 지표 레이어와 계절 결정 화면 (클라이언트)
- 내용: 교통 혼잡·셀 기온·침수 수심 레이어 전환, 5대 지표 패널, "계절 진행" 버튼과 보좌관 브리핑 표시.
- 완료 조건: 헤드리스 셀프테스트에 레이어·계절 진행 경로 추가, 화면 캡처.

### 13. 2단계 시나리오 테스트 (QA)
- 내용: "가로수를 심으면 그 블록 폭염 노출이 준다", "투수성 포장을 하면 최대 수심이 준다", "세율을 올리면 세수는 늘고 토지가치는 준다" 같은 방향성 시나리오.
- 완료 조건: `tests/scenarios`에 추가, CI 통과.
